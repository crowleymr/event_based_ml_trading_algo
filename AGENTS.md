# Repository agent instructions

## Research authority and scope

- Read `docs/FSD_v2.md`, the current implementation plan, decisions and completion evidence before changing research behavior.
- Preserve locked Slice 1 rules unless the human explicitly approves a research-policy change.
- The completed final test is descriptive. Never use it to choose, tune or reject features, models, portfolio engines or parameters. New selection work requires a new holdout/data vintage and documented protocol.
- Keep `trading_pipeline.run` as the authoritative execution path. Reporting, notebooks and user interfaces are read-only consumers of completed run artefacts.

## Evidence policy

- Every numeric result, summary statistic, table and chart used in documentation, reporting or papers must be generated by repeatable code from canonical data or immutable artefacts under `runs/`.
- Agents and operators may overlay semantic interpretation, but must not hand-enter, transcribe, estimate or silently recompute reported numbers in prose.
- Generated outputs must record the source run ID, input artefact paths and hashes, code version and generation timestamp where practical.
- Correct source data, derivation code or report generation and refresh downstream outputs. Do not manually patch a published number, table or chart.
- Keep raw run artefacts immutable. Generate reports in a separate output directory.
- Clearly distinguish observed facts, generated evidence, interpretation, assumptions and pending human decisions.

## Engineering practice

- Prefer deterministic CPU-first behavior, fixed seeds, explicit schemas and fail-fast validation.
- Maintain point-in-time joins, boundary purge/embargo, T+1 execution and transaction-cost reconciliation.
- Do not silently substitute identifiers, facts, missing held prices, unavailable data or alternate estimators.
- Keep local-first layered boundaries; do not add microservices, training notebooks or duplicate orchestration paths without an approved need.
- Add proportionate tests and record verification in `docs/IMPLEMENTATION_LOG.md`.

## Assignment integrity

- AI may structure, explain and generate reproducible evidence, but must not fabricate the student's first-person reflection, understanding, critique or knowledge gaps.
- Mark material requiring personal evidence as a student prompt. Preserve factual AI-action records separately from student-authored reflection.
